## Editorial changes

Every lesson now explains its concepts before asking for an implementation. New terminology has context, worked examples use the fictional Northstar Motors project, guided actions state expected observations, and independent practice has acceptance criteria. Key ideas, actions, warnings, and checks use restrained quote-style callouts.

The final foundation sequence creates the learning org before asking the learner to navigate it: CRM → Salesforce and orgs → Playground setup → navigation → objects, fields, and records.

The second review corrected missing starter-schema setup, restricted-user prerequisites, preservation of browser-built org changes, activity settings for Tasks, reproducible sharing experiments, batch fixture counts, required API response fields, callout ordering, component state reset, event-test isolation, and local Jest setup. It also separates test-only HTTP mocks from browser demonstrations.

Senior review strengthens supplied fixtures, same-key processing order, external-to-Salesforce status mapping, provider-response examples, concurrent-update reasoning, review artifacts, and the local capstone execution path. Job Research keeps training evidence distinct from employment and includes an explicit setup contract for the live-coding exercise. The self-check review replaces implausible distractors with realistic Salesforce misconceptions and checks that each question still has one correct answer.

## Limits of the evidence

No Salesforce org deployment, Apex compilation, Apex execution, Flow run, LWC compilation, or live Agentforce conversation was performed during this authoring work. The lessons distinguish sample data, local simulations, unit mocks, and real org checks. Learners must run the specified org checks and record their actual results.

Text and images are ready for manual transfer to Skool. This publication does not automatically create Skool lessons, verify paid membership, send email, or grant instructor review acceptance.
