Create a Case that a human can find in a support queue. Handoff in this version means creating work for a human through a Case. A queue is a shared work list for designated employees; it does not mean a live operator has immediately joined the conversation. Omni-Channel and a public messaging deployment are not required for the main demonstration. The agent may report a Case number only after the Flow creates and retrieves the record successfully.

## 04 · Create the Flow contract

Create an Autolaunched Flow (No Trigger), API SAM_Create_Demo_Handoff. Inputs: Text reason and optional Text testDriveId. Outputs: Text resultCode, resultMessage, caseId, caseNumber. Keep user context. Reject a blank reason with resultCode=INVALID_REASON and a useful message. If testDriveId is provided, retrieve the accessible Test Drive and return INVALID_BOOKING without creating a Case if it cannot be found.

## 07 · State the repeat limitation

This minimal Case Flow has no durable idempotency key, so a repeated invocation can create another Case. After success, the conversation should reuse the returned number rather than invoke creation again without a new reason and confirmation. A production version needs backend duplicate protection and a policy for unknown outcomes; conversation instructions alone do not provide that guarantee.
