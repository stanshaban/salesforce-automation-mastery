Connect Apex and Flow with separate confirmation for each operation that changes data. Action inputs are the values an operation needs. Outputs are structured evidence for the agent's response. Require user confirmation is an action setting: the user can inspect the proposed change and decline it. A freely generated approved Boolean is not a substitute for this control. Backend validation remains necessary even when the conversation requests confirmation.

Catalog reads do not create records. Declined confirmation leaves the corresponding CRM data unchanged. Success is based on the action result, not merely the user's intention. Three actions are connected; the two writes require their own confirmation.
