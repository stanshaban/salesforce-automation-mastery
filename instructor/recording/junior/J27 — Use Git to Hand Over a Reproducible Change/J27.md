## 02 · Distinguish source history from the running org

> 🎬 ЭКРАН. Раздел «Distinguish source history from the running org». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Git records versions of files. Salesforce stores the active configuration and business records in an org. These are related but not automatically identical. A working field created in Setup will not appear in a local repository until the relevant metadata is retrieved. A local code edit will not run in the org until it is deployed successfully. Metadata describes configuration and code: objects, fields, permission sets, Flow definitions, components, and other supported types. Business records are the customers and appointments stored using that configuration. A normal metadata deployment does not automatically recreate all of your synthetic test records. The handover therefore needs both a metadata plan and a sample-data setup explanation.

## 03 · Prepare a reviewable Git change

> 🎬 ЭКРАН. Раздел «Prepare a reviewable Git change». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Use the SAM repository as a template to create your own repository when that route is appropriate. Choose public only if you are comfortable showing its contents to everyone; a private repository requires explicitly granting the instructor access. Keep your solution work in your own repository rather than opening a solution PR into the course curriculum. A branch is a separate line of file changes. A commit is a recorded snapshot with a message. A pull request asks a reviewer to inspect the proposed difference between branches. Create a small branch for the assignment, inspect git status, and review git diff before staging files. Stage the intended paths rather than blindly adding every file in the workspace.
