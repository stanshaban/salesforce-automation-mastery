## 02 · Describe the requested action

> 🎬 ЭКРАН. Раздел «Describe the requested action». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Oleg says that Max should see tomorrow's test drive. Before configuring anything, make that sentence precise. Max needs to sign in, read Test Drive records, read the relevant fields, and access the particular appointment. If he must change its time, the required action is different. Access without a user, record, field, and operation is too vague to test. Organization access concerns entry into the environment, including an active account and applicable login controls. Object permissions describe operations such as Create, Read, Edit, and Delete on a category of data; people often abbreviate these as CRUD. Field-level security, or FLS, describes which fields are readable or editable. Record access concerns the individual records a user can reach within those object operations.

## 03 · Distinguish similar symptoms

> 🎬 ЭКРАН. Раздел «Distinguish similar symptoms». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Imagine that Anna owns TD-001 and Max does not. First, Max cannot sign in. Sharing TD-001 does not repair the login problem. Second, Max can sign in but lacks Read on Test Drive. A record share does not substitute for object Read. Third, he can read the appointment but not a protected field. Increasing record sharing does not fix a deliberately restricted field. Fourth, Max has the relevant object and field permissions but no access to the private appointment. This is the situation where record-sharing mechanisms become relevant. This sequence is a useful model for ordinary interactions, not a claim that every execution context is identical. Developer features, elevated permissions, and specialized access controls need explicit consideration in later lessons.
