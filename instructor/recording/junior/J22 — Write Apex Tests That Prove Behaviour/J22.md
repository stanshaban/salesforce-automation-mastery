## 02 · A test is a claim with executable evidence

> 🎬 ЭКРАН. Раздел «A test is a claim with executable evidence». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

A useful test states what should happen for known inputs and checks the result. Code coverage measures which executable lines ran; it does not prove the business rule was correct. A test that calls a method without assertions can execute many lines while allowing a wrong result to pass unnoticed. Start with a pure function from J18. A deterministic input and expected output make the purpose clear. Then test the record behaviour from J20 with synthetic data created by the test. Avoid depending on ordinary records already present in the org. An isolated test should explain its own setup and survive changes to unrelated sample data.

## 03 · Separate setup, execution, and assertions

> 🎬 ЭКРАН. Раздел «Separate setup, execution, and assertions». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

An Apex test method is marked @IsTest. The test creates its inputs, performs the operation, and checks the result with assertions. Test.startTest and Test.stopTest delimit the operation under test and provide the documented testing behaviour for limits and asynchronous work. They do not turn a weak assertion into a strong one. For the trigger tests, create a Vehicle with a Name, Model, and appropriate Status, and a fictional Contact with LastName. Create Test Drive records using those IDs and a future Scheduled_At__c. Use Confirmed when testing a valid confirmation, so the create-only Requested reminder Flow is not accidentally the central subject of that particular test. Test the Flow interaction separately.
