## 02 · A query reads; DML changes stored records

SOQL, the Salesforce Object Query Language, selects records and fields. DML, or Data Manipulation Language, creates, updates, deletes, or otherwise changes records. Reading a Test Drive into an Apex variable does not itself change the stored appointment. Assigning a different value to that variable also does not persist it until an appropriate DML operation succeeds. Oleg asks for a small function that cancels Requested appointments for a supplied set of vehicles. The caller supplies vehicle IDs, which identify records. The method should ignore an empty input, query eligible appointments once, prepare the changes, and update the collection once. It must not cancel Confirmed appointments merely because they concern the same vehicle.

## 03 · Make access mode explicit

> 🎬 ЭКРАН. Раздел «Make access mode explicit». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

The example deliberately uses WITH USER_MODE for the query and update as user for DML. This makes the intended access mode visible instead of relying on version-sensitive defaults. The project targets API 68.0. Current documentation differs from older material about defaults, so use explicit modes and inspect the documentation version when maintaining older code. User-mode operations enforce applicable user access, including object and field permissions and record-sharing behaviour. The fields used in query conditions matter too. A class declared with sharing is not, by itself, a complete statement that every object and field operation has been authorized. Keep class sharing and database-operation access mode conceptually separate.
