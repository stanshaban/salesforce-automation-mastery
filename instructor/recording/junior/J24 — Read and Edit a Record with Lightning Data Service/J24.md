The preview from J23 contained only browser data. Anna now needs to edit the scheduled time and status of a real Test Drive record that she can access. For a standard record-editing task, begin with Salesforce base components backed by Lightning Data Service rather than immediately writing a custom Apex controller. Lightning Data Service, often abbreviated LDS, supports record access for these components and works with the platform's permission model. The standard record form can display and edit selected fields, handle a normal save, and show supported errors. This reduces code you would otherwise need to write and maintain. It does not mean the application no longer needs testing or a correct underlying sharing design.

## 03 · Use the current record context

A record page has a current record. The public recordId property receives that context when the component is placed in a supported record-page environment. The @api decorator marks the property as part of the component's public interface. It does not magically supply an ID in every possible container. A component on an ordinary App Page needs a different, explicit way to identify a record. The JavaScript imports object and field references from the Salesforce schema. These imports make the intended metadata dependencies visible. The fields array contains only Scheduled At and Status for this task, not every field in the object. The form uses mode edit and provides its own standard save and cancel behaviour.
