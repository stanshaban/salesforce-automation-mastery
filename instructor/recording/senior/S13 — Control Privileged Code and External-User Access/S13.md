## 02 · Name the caller and the requested action

> 🎬 ЭКРАН. Раздел «Name the caller and the requested action». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

An external portal asks Salesforce to retrieve Irina's appointment. The request contains an appointment Id and a customer identifier. Neither value is proof that the caller is entitled to that appointment. Authentication establishes who the caller is; authorization establishes what that identity may do. Input validation checks whether the supplied values are acceptable for the operation. These checks solve different problems. A trust boundary separates information or actions with different assumptions about who controls them. Browser input, integration payloads, and model-generated tool arguments should cross that boundary as untrusted data. The server should derive or verify the permitted customer relationship rather than accepting a caller's claim that a record belongs to them.

## 03 · Read both the class and the operation mode

> 🎬 ЭКРАН. Раздел «Read both the class and the operation mode». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Sharing keywords govern record-level behavior in Apex contexts, while database operation modes affect the operation's security checks. With API 68.0, the newer default database mode is user mode. An explicit WITH USER_MODE query applies the user's sharing, object, and field checks even when the surrounding class is declared without sharing. Conversely, specifying system mode does not mean that a with-sharing class has automatically become without sharing. This is why 'the class is with sharing' is not a complete security review, and 'Apex always ignores permissions' is an outdated blanket statement. Inspect the class version, call path, sharing declaration, and each operation's intended mode. Explicitly document any elevation rather than depending on an implicit default inherited from an old example.

## 04 · If elevation is needed, make its scope small

> 🎬 ЭКРАН. Раздел «If elevation is needed, make its scope small». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

A maintenance service might legitimately update a derived status across records that Anna cannot edit directly. That does not justify exposing an unrestricted 'update any object' method to her browser. Define the exact action, allowed records, permitted fields, initiating identity, and auditable reason. Keep privileged code behind a narrow boundary and validate its caller before performing elevated work. Use an allowlist when client input controls a structural choice such as a sort field or operation name. Bind values in queries where supported, but do not assume a bound filter value validates an independently concatenated field name. If using stripInaccessible, use the returned cleaned records and understand that field stripping is not a substitute for the full record-access policy.
