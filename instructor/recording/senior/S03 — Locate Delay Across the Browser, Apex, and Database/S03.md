## 03 · CPU time is only one clock

> 🎬 ЭКРАН. Раздел «CPU time is only one clock». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Apex CPU time measures application-server processing attributed to the transaction. The database-processing portion of SOQL and DML, and time waiting for an external callout, are not counted as Apex CPU. Application work around those operations can still consume CPU. Consequently, a request can take several seconds while its reported CPU is much smaller. It can also fail the CPU limit even when its queries individually look quick. The synthetic example below places an external availability check on the critical path. The critical path is the chain of dependent work that determines when the user can continue. If rendering requires the callout result, improving a small collection loop will not remove the wait for that result. If the availability check can move to a later explicit step without breaking the business promise, the dependency itself may be the more valuable design question.

## 04 · Test competing explanations

> 🎬 ЭКРАН. Раздел «Test competing explanations». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Write two hypotheses: the slow callout controls the delay, or a large response controls browser rendering. For the first, replace the external dependency with a controlled test double in a suitable test path and compare the request's structure and elapsed behavior. A test double is a stand-in with a deliberate response, not a secretly faster production service. For the second, compare a reduced required field set and a smaller initial result page while keeping the user task equivalent. Change one meaningful variable at a time. Keep the same user permissions, filters, and application revision. Record whether caches were already populated. Capture several runs, including errors, rather than keeping only the fastest example. Heavy debug logging can affect an experiment and produce large files; use an appropriate logging scope and avoid publishing records or credentials.

## 05 · What a small org can and cannot establish

> 🎬 ЭКРАН. Раздел «What a small org can and cannot establish». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

In a training org, you can compare two LWC rendering approaches, observe request timing, or inspect a bounded Apex collection operation. These experiments teach how to attribute delay. They do not reproduce production network paths, a large sharing model, data skew, or concurrent dealer traffic. A good submission states the exact claim it supports, such as 'this change reduces repeated client processing for this fixture.' Your evidence package should include a sanitized timeline, the relevant code difference, raw observation rows, and a short explanation of remaining uncertainty. Avoid exporting an entire browser archive without reviewing its contents: network captures can include sensitive headers and data. A concise redrawn timeline is often sufficient for a classroom review.
