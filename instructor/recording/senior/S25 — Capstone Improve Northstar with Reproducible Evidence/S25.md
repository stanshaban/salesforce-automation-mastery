Include the problem brief, baseline revision, changed revision, fixture, raw results, and the smallest relevant diff. Add tests for empty input, ordinary input, a mixed collection, and the failure that originally motivated the change. For access-related work, include a denied case under the relevant security context. For asynchronous work, include a repeated or uncertain outcome. Write one ADR explaining the selected approach and an alternative. Add a runbook for release or recovery appropriate to the change. A local algorithm improvement may need only a simple rollback procedure; a data backfill needs separate recovery reasoning. Scale the documentation to the actual risk.
