Northstar's appointment trigger validates status changes, updates a vehicle summary, creates a reminder, and calls a helper with unclear side effects. Nobody can confidently explain why some conditions are repeated. Oleg wants a new cancellation rule, but a full rewrite would change too many behaviors at once. A characterization test records the behavior of the existing implementation for a defined input. It is useful when documentation is incomplete. It does not declare every observed behavior correct. If the old handler creates duplicate reminders, a characterization test can reveal that fact, but the business still needs to decide the intended behavior before a corrective change.

## 03 · Build a behavior map before choosing a new design

List entry points, records read, records changed, external effects, and the conditions controlling each effect. Include other automation that can run in the same transaction. A trigger handler is not isolated merely because it is stored in one class. A Flow may update the record again, and an integration may enter through a different route. Use the synthetic cases below to define a minimal behavior envelope. An envelope is the set of behavior you intend to keep stable during the first change. Include empty input, a normal transition, an unchanged status, a mixed bulk collection, and a rejected transition. Count side effects as well as checking the final field value.

## 04 · Extract one responsibility behind a seam

> 🎬 ЭКРАН. Раздел «Extract one responsibility behind a seam». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

A seam is a boundary where one part of the implementation can be replaced or tested independently. Start by extracting a pure status-decision function: given old and new state, what action should occur? Keep the trigger's collection handling and persistence contract stable while this decision logic moves. A pure function returns a result without performing hidden database or network work, which makes it easier to test. Do not immediately create a large framework with many layers. The first extraction should reduce a specific source of uncertainty. For example, separating 'should create a reminder' from 'insert reminder records' lets tests verify transition decisions without making every test depend on a complete org configuration.

## 05 · Use meaningful regression evidence

> 🎬 ЭКРАН. Раздел «Use meaningful regression evidence». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Tests should verify outcomes and absence of unintended work. A line-coverage number only shows which lines executed; it does not prove that a reminder was created once, that a denied transition stayed denied, or that a later batch of trigger records was processed. An early return controlled by one transaction-wide static Boolean is a useful review target. It can suppress legitimate later work as well as recursion. Prefer business transition checks and deliberately scoped coordination over a blanket 'already ran' flag. Any stateful guard should explain what it tracks and when repeated processing is valid.
