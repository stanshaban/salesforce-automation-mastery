## 02 · Indexes narrow a search only when the filter helps

> 🎬 ЭКРАН. Раздел «Indexes narrow a search only when the filter helps». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

An index is a data structure the platform may use to locate matching records efficiently. Selectivity describes how narrowly a condition reduces the candidate data set, under the optimizer's rules. A field can have an index while a particular value matches most records. In that case, following the index may not be the cheapest plan. Anna opens active appointments at her dealer. A year ago, Status__c = 'Requested' matched a small fraction of appointments. In the synthetic growth case, a failed completion process leaves most appointments Requested. The query text is unchanged, but the data distribution is different. Adding an index without examining that distribution may leave the underlying problem untouched.

## 03 · Read a plan as an estimate

The Query Plan tool exposes candidate plans and estimates such as cardinality and relative cost. Cardinality is the estimated number of matching rows. A plan is evidence about how the optimizer sees this query in this environment; it is not a promise of a particular number of milliseconds. Different filters, values, and data volumes can produce different plans. The synthetic snapshots below deliberately omit exact platform threshold calculations. They show a broad status filter and a narrower combination of dealer and date. In the starter, Dealer_Code__c is a proposed exercise field, not existing metadata. If you add it for a local experiment, record its definition and whether an index is actually available. Do not label an arbitrary custom field 'indexed' because its name sounds important.

## 04 · Keep query design and application design connected

> 🎬 ЭКРАН. Раздел «Keep query design and application design connected». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Request only fields needed for the current operation, use appropriate filters, and paginate when the user cannot meaningfully consume every row at once. Reducing selected fields can reduce payload and memory even when it does not change the leading query plan. Pagination choices have their own contracts: SOQL OFFSET has a maximum offset and does not provide a stable snapshot across changing data. Do not move a broad query into Batch and conclude that the query is fixed. Batch can change how work is divided, but start still needs a viable selection strategy. Likewise, replacing the query with a cache creates freshness, invalidation, and authorization questions. Consider those alternatives only when they fit the business journey.
