Max can edit an East appointment even though the team deleted a sharing rule. The deletion removed one source of record access, not necessarily all sources. ## 03 · Muting is local to a permission set group

> 🎬 ЭКРАН. Раздел «Muting is local to a permission set group». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

A permission set group bundles permission sets for a work responsibility. Its muting permission set removes selected permissions from that group's contribution. It is not a global deny that overrides the profile, a separately assigned permission set, or another group. This additive model explains why a muted permission can remain effective. The synthetic inventory below gives Max Edit from two independent places. Muting the group removes one contribution; the direct assignment still provides Edit. Removing the direct assignment may still be insufficient to prevent editing a particular record if another object-level source remains. Also inspect dependencies: muting a foundational permission can affect related permissions within the group's effective result.

## 04 · Build a removal plan with observable outcomes

> 🎬 ЭКРАН. Раздел «Build a removal plan with observable outcomes». Продолжай показ подготовленного примера. Выдели входные данные и решение именно этого раздела. Не прокручивай целый урок вместо демонстрации. Если это аналитическое упражнение, заполняй его рабочую таблицу по одному решению.

Start with the business reason: Max should stop editing East appointments after temporary collaboration ends, while continuing to edit his approved West work. Determine whether the intended change concerns object Edit, East record access, or both. Removing object Edit globally might solve the East symptom by unnecessarily breaking West work. Create a before-and-after matrix of allowed and denied actions. Include normal interface use, relevant API or Apex entry points, sensitive fields, and any supported restrictions. Restriction rules can narrow existing record visibility for supported objects and contexts; they do not grant missing access. Do not assume that multiple matching restriction rules combine into a reliable AND policy.
